Розширення для браузера, яке робить **конспект будь-якого відео на YouTube** через майже будь-якого ШІ-провайдера (OpenAI-сумісні API, Google Gemini, Anthropic, локальні моделі через Ollama / LM Studio).

```
┌──────────────┐   субтитри    ┌──────────────────┐   конспект   ┌──────────────┐
│  YouTube     │ ────────────▶ │  ШІ-провайдер    │ ───────────▶ │  панель на   │
│  (сторінка)  │               │  (ваш вибір)     │              │  сторінці    │
└──────────────┘               └──────────────────┘              └──────────────┘
```

* **Один рушій — ШІ.** Конспект пише обрана модель; не-ШІ підсумовування немає — його конспекти були набором повторів і уривків, тому рушій видалено. Стратегія адаптивна: якщо весь транскрипт вкладається в безпечний бюджет контексту (128 000 токенів за замовчуванням), це **один запит** — навіть для тригодинного відео (~64 000 токенів). Усередині цієї однієї відповіді готовий TL;DR, ключові моменти й розділи з'являються в панелі в міру генерації — щойно модель закрила значення і воно пройшло перевірку, а не після останньої дужки. Якщо транскрипт не вкладається, вмикається паралельний map-reduce з великими фрагментами (6 000 токенів): готові фрагменти з'являються в панелі в міру відповідей, а підсумковий TL;DR збирається лише після обробки всього транскрипту, без втрати таймкодів і з явною позначкою, якщо якась частина не обробилася. Є стрімінг, скасування, повтори, автоперемикання на резервного провайдера, кеш конспектів і кеш розбору фрагментів. Якщо Chrome/Firefox вивантажить фоновий процес посеред роботи, панель запропонує кнопку **«Продовжити»** і відновить саме збережене завдання з уже готових фрагментів — за умови, що транскрипт, промпт, модель і налаштування не змінилися.

## Можливості

| Розділ | Що всередині |
| --- | --- |
| **Огляд** | TL;DR, розділи за змістом або за главами (заголовок цілком — посилання на момент відео), ключові моменти й тези з таймкодами, висновки, «що можна зробити», цитати |
| **Питання** | Q&A за змістом: відповідь моделі з цитатами-джерелами. Без налаштованого провайдера — резервний пошук за транскриптом (BM25), який цитує фрагменти, а не переказує їх |

Ключові слова, сутності, статистика, перевірка чисел і діагностика запуску лежать під згорнутим «Подробиці запуску» внизу панелі — вони пояснюють, як зроблено конспект, а не сам конспект.

Додатково: кругла кнопка на сторінці відео, popup зі швидкими діями, вікно налаштувань, експорт у Markdown / TXT / JSON (зокрема разом із транскриптом), кеш та історія конспектів, гарячі клавіші, контекстне меню за посиланням на відео.

## Встановлення

### Готовий архів

Візьміть ZIP з [Releases](https://github.com/Smokelweiss/OpenSummary/releases/latest) і розпакуйте — збирати з вихідників не обов'язково. Кроки `npm run icons` / `npm run build` нижче потрібні лише під час роботи з кодом.

### Chrome / Edge / Opera (розпаковане розширення)

1. `npm run icons` і `npm run build` — з'являться `dist/opensummary-chrome/` і ZIP-архів.
2. `chrome://extensions` → увімкніть **Режим розробника** → **Завантажити розпаковане розширення** → виберіть `dist/opensummary-chrome`.
3. Відкрийте будь-яке відео на YouTube: праворуч унизу з'явиться кнопка OpenSummary.

### Firefox

`dist/opensummary-firefox/` — збірка з event-page замість service worker (`about:debugging` → **Цей Firefox** → **Завантажити тимчасовий додаток** → `manifest.json`). Потрібен Firefox 128 або новіший (там повністю підтримано MV3-модулі фону та `optional_host_permissions`).

### Перший запуск

* Відкрийте налаштування → **Провайдери ШІ** → «Додати провайдера» → виберіть сервіс → вставте API-ключ → «Перевірити зв'язок» → «Зберегти». Після цього кнопка «Саммарі» в панелі рахує конспект моделлю.

## Використання

* **Кнопка на сторінці** або `Alt+Shift+S` — відкрити/сховати панель; `Alt+Shift+D` — одразу порахувати конспект.
* **Popup розширення** — кнопка «Саммарі з ШІ» для активної вкладки та список недавніх конспектів.
* **Таймкоди** в конспекті клікабельні — плеєр перемотується на потрібний момент.
* **Експорт**: унизу панелі — «Копіювати» і «Завантажити» (Markdown / текст / JSON, опційно разом із транскриптом).
* **Лише потрібне на екрані.** У шапці — дві вкладки (Огляд, Питання) і три кнопки: саммарі, швидкі налаштування, закрити. Режим, провайдер, модель, мова й обсяг живуть у швидких налаштуваннях за шестірнею одним рядком, «Усі налаштування» — там же праворуч. Статистика, ключові слова, сутності та перевірка чисел — під згорнутим «Подробиці запуску» внизу панелі. Окремих вкладок «Розділи», «Таймлайн» і «Транскрипт» немає: розділи живуть в «Огляді», у YouTube є своя панель із пошуком. Панель за замовчуванням світла, перемикач теми — сонце/місяць у шапці (або «Налаштування → Тема панелі»).
* **Немає субтитрів?** Панель візьме текст із вбудованої панелі «Транскрипт» на сторінці: розширення відкриє її у фоні й одразу закриє, сторінка не смикається і не прокручується. Якщо й її немає — на екрані буде зрозуміла помилка з кнопкою «Взяти транскрипт зі сторінки», а не порожня панель. Ручної вставки тексту більше немає.

## Швидкість

Потокові пункти панелі відмальовуються не частіше одного разу на кадр, а читання транскрипту зі сторінки не показує панель YouTube: її переносять за екран до появи, закривають і повертають на місце, причому сторінка не зміщується — позиція плеєра на екрані зберігається. Браузерний E2E замірює відкриття панелі, відмальовування готової відповіді та час до першого пункту і падає, якщо бюджет перевищено.

## Налаштування

* **Інтерфейс** — мова, тема, ширина й спосіб показу панелі (вбудована колонка або поверх сторінки), автозапуск.
* **Конспект** — мова результату, обсяг, тон, таймстемпи, власні інструкції для моделі.
* **Тонке налаштування ШІ** — стратегія (авто / один запит / map-reduce), бюджет контексту, розмір чанка, паралельні запити, temperature, ліміт токенів відповіді, повтори, таймаут, стрімінг, резервний провайдер, кеш конспектів і кеш розбору фрагментів, власна системна інструкція.
* **Дані та приватність** — де зберігати ключі (постійно або до закриття браузера), кеш та історія, експорт/імпорт, скидання.

## Приватність

* Ключі API та налаштування зберігаються **лише у вашому браузері** (`chrome.storage`) і не надсилаються розробнику.
* Провайдеру йде **текст субтитрів** і запит на конспект — більше нічого. Хост провайдера видно в налаштуваннях, доступ до довільних хостів запитується окремо. Резервний пошук за транскриптом працює офлайн і нічого не надсилає.
* Жодної аналітики й телеметрії. Подробиці — у [PRIVACY.md](PRIVACY.md).

## Розробка

```bash
npm test          # 361 тест: ШІ на mock-провайдерах, потоковий протокол, субтитри, фон (заглушка chrome),
                  # панель на стаб-DOM, імпорт відповіді YouTube, ворожий корпус і фаззинг розбору
npm run quality   # офлайн-замір без моделі: межі чанків за змінами теми та перекриття
npm run fixture -- status  # імпорт/очищення реального ytInitialPlayerResponse: analyze|sanitize|status (tests/fixtures/youtube/)
npm run e2e       # справжній Chrome/Chromium: чернетка, підсумок, фолбек і AUTH; скріншоти в dist/e2e-artifacts/
npm run e2e:rounds -- --cycles 20   # багаторазові прогони за маршрутами транскрипту; звіт у dist/e2e-rounds/
OSUM_YOUTUBE_TEST_URL="https://www.youtube.com/watch?v=..." npm run e2e:youtube
                  # живий YouTube (субтитри + ручна вставка), ШІ — локальний мок; потрібна мережа
                  # --cycles N повторює повний шлях N разів (замір частки успішних прогонів),
                  # OSUM_CHROME_PROXY=socks5://127.0.0.1:9150 — мережа, де youtube.com
                  # заблоковано: тестовий браузер піде через ваш локальний проксі/VPN
npm run live      # живий цикл: справжній YouTube + OpenRouter у справжньому Chrome, звіт і скріншоти
                  # ключ лише з OSUM_OPENROUTER_KEY / --key-file поза репозиторієм; див. нижче
npm run bench     # ручний живий замір: --live --transcript=FILE + OPENROUTER_API_KEY (прапорці: --help)
                  # без ключа: --live --mock --synthetic (SSE-мок) і --no-stream для порівняння
npm run bench:sim # офлайн-стенд без ключа: запити, хвилі Map, раунди Reduce, критичний шлях
npm run bench:report # медіана та розкид за кількома живими звітами
npm run icons     # генерація PNG-іконок (власний кодувальник, без залежностей)
npm run check     # статичні перевірки: синтаксис, manifest, id елементів сторінок, імпорти й експорти,
                  # типи повідомлень і портів, виклики невідомих функцій, пошук секретів
npm run build     # збірка dist/ (Chrome + Firefox, ZIP і розпаковані папки)
```

Залежностей немає взагалі: усе на стандартній бібліотеці Node ≥ 18. Збірка не потрібна — розширення завантажується з вихідників як є. Браузерний E2E сам знаходить Chrome/Chromium (або шлях у `OSUM_CHROME` / `--chrome`), збирає розширення, піднімає локальну сторінку та SSE-мок і не чіпає звичайну збірку. Окремий онлайн-сценарій `npm run e2e:youtube` відкриває справжнє відео (URL у `OSUM_YOUTUBE_TEST_URL`) у тимчасовому профілі й перевіряє отримання субтитрів і ручну вставку; ШІ-провайдер у ньому теж мок, тому ключ не потрібен. Живий benchmark запускають вручну: `npm run bench -- --live --transcript=FILE` з ключем у змінній середовища; усі прапорці виводить `npm run bench -- --help`.

Живий цикл `npm run live` — це повний шлях «справжній YouTube → справжній провайдер → панель»: тимчасовий профіль Chrome, реальний ключ OpenRouter зі змінної середовища або файлу поза репозиторієм, звіт у `dist/live-artifacts/report.jsonl` (код помилки, стратегія, час до першого пункту, лічильники), скріншот кожного збою. `--repeat N` ганяє одне відео кілька разів (кеш вимкнено) — так вимірюється частка успішних конспектів, а не один вдалий прогін. Ключ ніколи не пишеться в проєкт, лог чи звіт.

### Структура

```
src/
  common/      константи, утиліти, сумісність Chrome/Firefox, storage-шар
  nlp/         схема результату та рендери, резервний пошук за транскриптом (BM25)
  transcript/  отримання субтитрів YouTube (сторінка + InnerTube), парсинг json3/vtt/srv1/srv3
  ai/          каталог провайдерів, універсальний клієнт, чанкування, промпти, JSON-ремонт, конвеєр
  background/  service worker: маршрутизація повідомлень, порти завдань, кеш, транскрипти
  content/     панель на сторінці (Shadow DOM), i18n, стилі, експорт, DOM-фолбек транскрипту
  popup/       popup розширення
  options/     сторінка налаштувань
tools/         генератор іконок, zip-пакувальник, збірка, перевірки
tests/         тести та фікстури
tests/e2e/     браузерний стенд (Chrome через CDP, SSE-мок, заглушка і живий YouTube)
```

### Архітектура двома словами

* Service worker — єдине місце, де виконуються мережеві запити та виклики моделей. Контент-скрипти лише малюють інтерфейс.
* Субтитри беруться трьома способами (у цьому порядку): `api/timedtext` за доріжкою з даних плеєра → `youtubei/v1/get_transcript` (той самий запит, що робить панель «Розшифровка відео»; не потребує PO-токена) → читання вже відмальованої панелі на сторінці. Останній варіант — резервний: він потрібен, якщо обидва API відповіли відмовою; панель при цьому схована до появи, закривається одразу після читання, а сторінка лишається на місці: розширення утримує плеєр у тій самій точці екрана.
* Контент-скрипти — класичні скрипти без модулів, спільний неймспейс `window.OSUM`.
* Довгі завдання йдуть через `Port` (`osum-task`) з подіями `stage / progress / stream-item / result / error / done` і keepalive кожні 15 секунд — так перевірені пункти з'являються до фінальної відповіді, а роботу можна скасувати.
* Відповідь моделі нормалізується в **одну схему** `SummaryResult` (див. `src/nlp/schema.js`), тому UI та експорт не залежать від провайдера.

## Діагностика

| Симптом | Що робити |
| --- | --- |
| «У цього відео немає субтитрів» | Увімкніть CC на сторінці й запустіть аналіз ще раз — або натисніть «Взяти транскрипт зі сторінки» |
| «Доріжка захищена PO-токеном» (`POT_REQUIRED`) | Спочатку розширення саме пробує `youtubei/v1/get_transcript` — той самий запит, що робить панель «Розшифровка відео», він не потребує PO-токена. Якщо й він не відповів, натисніть «Взяти транскрипт зі сторінки» (читається відкрита панель) або вставте текст вручну. У «Подробицях» тепер видно, що саме знайшов скрапер: `panel`, `rows`, `timecode cells`, `duration` |
| «На сторінці не знайшлася панель «Транскрипт»» | Розгорніть опис і натисніть «Показати текст відео» — або відкрийте панель «У цьому відео» → «Розшифровка відео». Якщо панель відкрита на вкладці «Епізоди», розширення саме перемкне її на «Розшифровку відео» й перечитає рядки. Рядки знаходяться за таймкодами, за будь-якої розмітки. Якщо панелі немає в самого відео (субтитри не опубліковані), конспект робити нема з чого. Довгі відео доскролюються повністю, тому розбір триває кілька секунд |
| «Модель вичерпала ліміт і не повернула текст» (`TRUNCATED`) | Зазвичай так поводяться «думаючі» моделі. Збільште «Максимум токенів відповіді», виберіть модель без режиму роздумів або увімкніть стратегію «фрагментами» — розширення саме повторить запит із більшим лімітом |
| ШІ не відповів (`EMPTY_RESPONSE`, `EMPTY_RESULT`, таймаут) | Панель показує картку з причиною та підказкою, а якщо конспект уже був на екрані (наприклад, з кешу), він лишається під карткою — без червоної плашки замість результату. Кнопка «Повторити» пробує знову (наприклад, після зміни моделі), «Налаштування» відкриває провайдерів. Одна порожня відповідь моделі дає другий шанс: розширення повторює запит у короткому форматі (1600 токенів, 45 с) |
| «Модель відповіла текстом без JSON» (`BAD_JSON`) | Модель проігнорувала JSON-формат. Розширення вже повторює запит у короткому форматі; якщо не допомогло — виберіть модель без режиму роздумів або зменште обсяг конспекту. У «Подробицях» видно текст, який повернула модель |
| «Замість конспекту модель повернула вердикт перевірки безпеки» (`MISROUTED_MODEL`) | Безкоштовний роутер надіслав запит моделі-класифікатору (`User Safety: safe` тощо). Повтор майже завжди потрапляє на пишучу модель; якщо це повторюється, виберіть конкретну модель замість `openrouter/free` |
| «Фоновий процес не відповів» (`WORKER_SILENT`) | Панель не отримувала ні подій, ні відповідей на свої пінги довше 30 с — зазвичай фон перезапустився. Натисніть «Повторити»; якщо не допомагає, оновіть вкладку. Модель, яка довго «думає» перед першим токеном, цією помилкою більше не вважається: пінги тримають прогін живим |
| Модель відповідає лише «роздумами» | Деякі безкоштовні моделі повертають порожній текст і роздум у полі `reasoning` (`openrouter/free` — типовий випадок). Розширення використовує це поле як відповідь, а якщо JSON у ньому немає — пропонує змінити модель на варіант без режиму роздумів |
| Моделі провайдера застаріли | Натисніть ⟳ поруч зі списком моделей у панелі (або «Завантажити моделі» в налаштуваннях) — список підтягнеться з API провайдера |
| ШІ: «Ключ відхилено (401)» | Перевірте ключ і доступ до обраної моделі; натисніть «Перевірити зв'язок» у налаштуваннях |
| ШІ: «Провайдер вимагає оплату (402)» | Виберіть безкоштовну модель (наприклад, із суфіксом `:free`) або іншого провайдера |
| ШІ: «Забагато запитів (429)» | Зменште «Паралельні запити», зачекайте хвилину або увімкніть резервного провайдера |
| Локальна модель недоступна | Запустіть сервер (`ollama serve`), перевірте порт і дозвольте доступ до `localhost` у налаштуваннях |
| «Транскрипт не вмістився в контекст» | Зменште «Розмір чанка» — конвеєр розіб'є відео на більшу кількість частин |
| Після перезапуску фонового процесу | Панель покаже окрему кнопку **«Продовжити»** з кількістю готових фрагментів і причиною зупинки; продовження не оплачує їх повторно. Якщо дані змінилися, кнопки немає; скасовані та завершені завдання не відновлюються |
| «Неповне охоплення» (`meta.complete=false`) | Частина фрагментів не обробилася після повторів (ліміт часу, помилка моделі або порожні відповіді). Конспект зібрано лише за успішними частинами і не збережено в кеш: зменште «Розмір чанка», знизьте паралельність або змініть модель і повторіть |
| «Один запит замість фрагментів» | Перевірте «Бюджет контексту» в налаштуваннях ШІ: він має відповідати вікну моделі. Для `openrouter/free` безпечно 128 000 із заявлених 200 000. Якщо провайдер усе одно відповідає помилкою контексту, розширення саме перейде на фрагменти |

У налаштуваннях → «Про розширення» → «Скопіювати діагностику» збирається звіт без ключів — його зручно додати до issue. Туди ж потрапляє **журнал транскрипту**: останні 20 спроб із маршрутом (`timedtext` / `get_transcript` / панель на сторінці), кодом помилки та лічильниками скрапера (`panel`, `rows`, `cells`, `duration`), від старих до нових.
